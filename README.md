# 聖地巡礼 · 调色对比生成器

这是一个独立的纯前端小工具

## 一键调色能力

- CDF 亮度曲线匹配：把实景照片的非线性影调匹配到动画截图
- MKL 二维色彩迁移：同时处理 Lab 的 a/b 相关性，减少色相搬运错误
- 天空/地景分区：两侧都识别到天空时分别迁移，失败自动退回全局路径
- 字幕带保护：动画统计默认忽略底部 12%
- 饱和度软提升与高光 Bloom
- 预览保持 1400px 流畅，导出时在原始分辨率上分块重放同一套调色
- 洋葱皮构图对齐：拖拽、缩放、裁剪后再进入调色
- 角色合成去色渗、光照融合、可调软阴影与颗粒匹配
- 调色参数自动恢复（图片不会写入浏览器存储）
- 基础调色无需 AI 下载；「加角色」「找最像」首次使用时才提示下载（会先说明大小、建议 Wi‑Fi），也可在「更多」里出门前一次性提前下载；下载中断后可继续
- 手机端内存保护、HEIC 明确提示与 EXIF 方向校正
- 导出 65³ `.cube` LUT（含影调、色彩、饱和度；不含空间相关的天空分区和 Bloom）

## 界面与交互（2026-09 重做）

设计目标：**户外单手用手机也顺手**。原来的界面是桌面三栏直接堆成手机长页面（预览在第 513px、调色滑杆在第 974px、导出在第 2122px，拖滑杆时看不到效果），规则也多。现在：

- **一屏到底**：顶栏 / 素材条 / 预览 / 操作区。预览永远在屏幕上，调色滑杆就在它下面；不需要滚动页面找控件。
- **一条主线，每步一个主按钮**：选动画截图 → 现场拍摄（或选已有照片）→ 自动调色 → 保存。素材条里「下一步该做的那一格」会高亮，取代原来的五步流程条。
- **界面阶段**由 `updateUI()` 统一切换：`empty`（空）→ `anime` / `photo`（只有一张）→ `ready`（两张都有，调色预览）→ `align`（构图对齐）。操作区只显示当前阶段需要的东西。
- **默认就是强光可读**：深色文字、粗描边、≥48px 触控目标；不再有单独的「强光」开关。取景叠加默认更实、带对比增强。
- **模型下载在需要时才问**：点「加角色」/「找最像」时如果模型还没下载，会先说清楚大小并建议 Wi‑Fi，而不是进站就弹一个阻塞式公告。
- **导出先看再存**：生成完进结果页，点「分享 / 存到相册」（手机）或「下载文件」。分享按钮自带新的用户手势，不会因为全分辨率渲染太久被系统拒绝。
- **拍完先确认**：取景器拍完显示成片，「重拍 / 使用这张」，而不是拍完立刻退出去才发现糊了。

### 被移除的功能与原因

之前的完整实现都在 git 标签 `pre-redesign-20260929` 里，想找回可以 `git show pre-redesign-20260929:app.js`。

| 移除的东西 | 原因 |
|---|---|
| 「点选补块」「磁性描边 / 锁定此轮廓」「点擦整块」 | 点一下自动圈一整片，结果不可预期，用户无法判断会锁定哪里。改成可预测的画笔：擦除 / 补回 + 撤销 + 双指缩放 |
| 算法抠像（`segment.js` 的启发式前景提取）、矩形/圆形/画笔三种圈选形状 | 效果不稳，还要先圈范围。现在只有「加角色」一键 AI 抠图，抠错了用「手动框选」和画笔修 |
| 抠图阈值 / 收边 / 去碎点 / 填洞 滑杆、光照融合 / 阴影 / 阴影方向 / 颗粒 滑杆、远景小人和 iPhone SAM 勾选框 | 普通用户不理解这些参数。改成固定的验证过的默认值；小角色漏检时给「加强搜索小角色」按钮；收边只保留一个滑杆放在修边面板里 |
| 五步流程条、动画主色色块、进站公告弹窗、强光模式开关、ⓘ 说明气泡 | 被「素材条高亮下一步」、上下文里的提示、默认高对比取代 |
| 风格预设（保存 / 应用 / 删除）、批量套用导出 | 使用率低、界面占地大；当前参数仍会自动恢复 |
| 滑动对比视频（WebM/MP4）、APNG 高清动图 | 需要页面保持前台录制 4 秒、兼容性差；GIF 已满足分享 |
| 预览里的「叠加 / 上下」对比模式、动画透明度滑杆 | 合并成一个：滑块左侧可切换「原图 / 动画」（点左上角标签）；上下对照仍可在导出里生成 |
| 取景器的「闪烁 / 分割」叠加、冻结、高清模式 | 户外只用半透明和轮廓；冻结后拍照拿的还是实时帧，容易误导；高清模式视野和取景框不一致 |
| 三个离线包 + 线路检测 | 合成「提前下载」一个按钮；诊断信息导出保留在「更多」里 |
| `cam/index.html`（与 `camera-probe.html` 完全相同的重复文件） | 无任何页面引用 |

## 本地开发（可选）

`启动圣地巡礼工具.command` 是 **macOS 专用** 的本地开发辅助，不是使用网站的必要步骤。它会启动一个带 COOP/COEP 响应头的本地服务：

在 macOS 上双击：

```bash
./启动圣地巡礼工具.command
```

也可以手动运行普通静态服务，但这会使 ONNX Runtime 退回单线程：

```bash
python3 -m http.server 8126 --bind 127.0.0.1
```

然后打开：

```text
http://localhost:8126/
```

双击启动器时，如果 8126 已被其他本地项目占用，会自动改用 8127–8136 中的空闲端口；终端窗口会显示实际地址。
推荐始终使用双击启动器，因为它会发送 COOP/COEP 响应头，让 AI 推理启用多线程。

`.claude/` 是编辑器与 AI 助手的本地配置目录（例如本地预览服务器的启动定义），因机而异，
不属于项目本身，已在 `.gitignore` 中忽略，不要提交。

## 文件说明

- `index.html`：页面结构
- `style.css`：界面样式
- `app.js`：界面编排（阶段切换、调色预览、角色合成、构图对齐、导出结果页、找图、离线模型）
- `image-io.js`：图片读取（EXIF 方向、HEIC/RAW 兜底、GPS）与预览尺寸缩放
- `gif.js`：零依赖 GIF 编码（动画→实景渐变动图）
- `camera/`：现场取景（摄像头会话、半透明/轮廓叠加、拍照、拍后确认）
- `color.js`：LAB 色彩迁移和 LUT 导出
- `qa/grade-qa.html`：调色开发验收页（真实素材、数值、性能、LUT 回验）
- `segment.js`：AI 抠图结果的后处理（阈值、去碎点、闭运算、羽化、裁切）
- `ai-segment.js`：浏览器内 AI 抠图（整图直抠 + 检测→裁剪→抠→合并流水线）
- `detect.js`：动画人物检测（YOLOv8s，先找角色框再抠，解决多人同框/小角色）
- `ort-env.js`：onnxruntime-web 加载与模型会话缓存
- `models/isnet-anime-fp16.onnx`：AI 抠图模型（ISNet-anime）
- `models/person-detect.onnx`：人物检测模型（deepghs/anime_person_detection，static-int8）
- `models/scene-embed-int8.onnx`：动画截图与实景图匹配模型（DINOv3 ViT-S/16）
- `sam-segment.js`：SlimSAM 点提示分割（ISNet 抠不出的小角色自动兜底）
- `models/sam-encoder.onnx` / `models/sam-decoder.onnx`：SAM 模型（Xenova/slimsam-77-uniform）
- `THIRD_PARTY_LICENSES.md`：模型与运行时许可来源
- `DEPLOYMENT.md`：公开部署、响应头与素材排除清单

## 开发验收

服务启动后打开：

```text
http://localhost:8126/qa/grade-qa.html
```

验收页会自动运行 CDF、天空检测、同图恒等、Bloom=0、65³ LUT 随机点回验和 1400px 性能测试，并展示旧版/新版视觉对比与天空掩膜。

正式页面也提供隐藏演示入口，便于走完整 UI 链路：

```text
http://localhost:8126/?qa-demo=1
```
